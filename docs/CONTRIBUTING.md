# 开发与维护约定

先阅读 [架构与模型边界](ARCHITECTURE.md)，再根据修改内容选择对应模块。保持改动聚焦，以可运行、可验证为准；不要求每个内部实现步骤都另行批准。

## 日常命令

在项目根目录使用支持当前 Vite 的 Node.js LTS 和 npm。已有锁文件时优先 `npm ci`；有意调整依赖后运行 `npm install` 并保留锁文件变更。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

`dev` 启动仅监听本机的开发服务，访问终端实际显示的地址。`build` 先进行 TypeScript 检查，再生成 `dist/`。`preview` 用于检查已构建结果，不代替构建步骤。

只运行相关测试时可使用：

```sh
npm test -- src/sim/engine.test.ts
npm test -- src/project.test.ts
```

## 改动原则

- 使用已有 TypeScript 类型，外部输入从 `unknown` 开始校验。避免以 `any` 或类型断言绕过端子、状态和存档格式检查。
- 命名说明对象或行为，复杂条件提取为小函数。注释解释电气假设、边界和原因，不逐句复述代码。
- 电气定义集中到 `src/sim/model.ts`；仿真规则放在 `engine.ts`；布局与图形保持独立。示例与用户接线使用同一条仿真路径。
- 界面不得写“点击 SB2 就打开 KM1/HL2”之类绑定。按钮只提交操作输入；线圈和灯由接线计算。
- 端子 ID 是存档中的稳定标识，不用数组下标、像素坐标或显示名称代替。布局调整不得改变电气连接。
- 参考图看不清的参数标注待核实。教学 L/N 当前只有逻辑意义，不补写未经确认的实物额定电压、电流、保护曲线或电机效果。
- 文件格式校验统一使用 `project.ts`，浏览器读写统一使用 `storage.ts` 的 `readStoredProject` / `saveStoredProject`。更改格式时编写显式版本迁移及测试，不静默丢弃旧数据，不绕过损坏存档的覆盖保护。
- 新依赖应解决明确问题，优先使用已有工具；避免为小功能引入整个框架。项目不依赖在线字体、图片或服务才能完成核心实验。

## 怎样逐步增加器件

1. **核对资料。** 记录器件来源、型号、端子标签、常开/常闭关系、操作方式，以及未确认的参数。图片资料索引位于 `docs/references/README.md`。
2. **补充模型。** 在 `model.ts` 添加器件、端子及触点或负载；新行为再扩展类型和仿真规则。仅作占位的器件明确列为未支持，不能只显示“正常运行”。
3. **确认固定配线。** 保持目前一对一端子映射；不同映射显式建模。不要因为两根引出线在画面上相交就建立连接。
4. **先验证行为。** 用端子连接数据测试释放、动作、断电、断线和相关错误接法；验证与既有接触器、保护触点的组合。
5. **补齐布局和外观。** 在 `layout.ts` 放置器件与所有端子，通过覆盖检查；`DeviceArt` 只消费状态绘制；`Bench` 只转发操作与接线事件。
6. **给出可复现示例。** 在 `examples.ts` 添加必要实验并说明操作结果；确认用户拆线、换端子、改颜色后仍按实际网络计算。
7. **检查兼容与说明。** 确认旧方案可用；需要新存档版本时增加迁移测试。同步更新实际支持能力和限制，运行相关测试与构建。

## 测试分层

| 层级         | 重点                                                                       | 当前入口                                                 |
| ------------ | -------------------------------------------------------------------------- | -------------------------------------------------------- |
| 仿真单元测试 | 点动、自锁、停止、触点联动、断线、短路、不稳定网络、未支持接法             | `src/sim/engine.test.ts`                                 |
| 状态转换测试 | 电源、器件输入、换线、复位及失焦后的瞬动释放                               | `src/sim/simulationState.test.ts`                        |
| 存档边界测试 | 有效往返、旧版本处理、未知端子、重复线、恶意字段、文件上限、颜色、有限坐标 | `src/project.test.ts`                                    |
| 本地读写测试 | 损坏或未知版本原文保护、重复初始化、写入前重读、读取失败、空间不足         | `src/storage.test.ts`                                    |
| 布局检查     | 模型端子都有位置；新增端子不遗漏；端子 ID 不重复                           | `src/layout.ts` 的覆盖检查，变更相关逻辑时补充针对性测试 |
| 浏览器验收   | 真实鼠标/键盘接线、按住与松开、缩放平移、断电编辑、错误反馈、保存恢复      | 在开发服务或构建预览中按操作步骤验证                     |

测试应覆盖有意义的结果，不只验证某个函数被调用。修改电气行为时用能复现问题的接线添加回归测试；纯图形、文案和低风险样式调整通常通过构建与浏览器检查即可。

常用验收线路是“按钮点灯”“接触器点动”和“自锁启停”。检查至少一次：松开启动按钮后自锁保持、停止后释放、拆去关键导线后动作消失、颜色或路径变化不影响动作、导入失败不丢失当前接线。相关检查通过后无需机械重复整套测试。

## 完成一次改动

提交或交付前简要说明改了什么、为何修改、实际运行了哪些检查，以及仍存在的能力边界。行为改动完成相关回归测试，并运行 `npm run build`；涉及交互时在浏览器检查真实操作。不要将未运行的测试或未实现的功能写成已完成。

保留用户参考资料和已有接线文件。大范围架构调整分成可运行的小步骤，优先提取稳定边界，避免在新增实验时同时重写全部界面与仿真。

视觉小样与正式入口分别标明完成状态。用户认可外观后，推广工作须核对正式画布和详情面板使用的实际组件，在普通/全屏、明暗及动作前后检查；只更新小样不算正式接入完成。用户接线经过已有导线或器件时应能继续布线路径，外观层不能截断编辑流程。
